# 首次进入页面的加载优化

## 已实现

- 原始 `routes-data.js` 继续作为内容来源；首页使用轻量目录，各条完整攻略按需加载。
- Pages 通过 Vite 生成压缩后的脚本、样式和带内容标识的文件名，路线详情和故事界面独立分包。
- 首页卡片使用 960/1440 像素 WebP，首图优先加载，屏幕外图片接近视野后再请求。
- 路线页先显示轻量地图，在介绍出现后换成原尺寸地图；坐标、点位、路径和缩放范围保持一致。
- Remotion 在介绍出现后准备第三幕的虚线，不阻塞首次地图显示。
- 照片预览和缩略图有独立副本；原图、菜单、作者、水印和来源字段保留。照片页未打开时不请求其中的照片。

## 发布和维护

1. 新增或替换图片后：`py -3.11 scripts/optimize-images.py`（Python + Pillow）。
2. 改变路线内容后：`npm run build:runtime`，然后运行本地服务器。
3. 发布前：`npm ci`、`npm run build:pages`、`npm run stage:pages-assets`。
4. 提交图片清单、选中的图片副本、源代码和内容文件。`feed-data.js`、`assets/runtime/`、`dist/` 由构建生成，不需要提交。
5. GitHub Actions 使用已提交的图片清单及图片，在构建时重新生成目录和完整攻略分包。

新增了 485 个 WebP 文件，但用户不会下载整个站点资产包。多数文件是按景点访问的预览/缩略图；原图留给放大查看。

## 浏览器观察

优化前的线上首页，在空缓存、桌面视口、4 Mbps/120 ms 网络模拟、CPU 2 倍减速条件下：40 个首页脚本，解压后 1,585,175 字节；首屏阶段加载资源共 14,173,816 字节；观察到 LCP 约 18.3 秒。

优化后的本地发布预览，在同样的模拟参数下：1 个首页脚本，解压后约 54,343 字节；首屏阶段加载资源共 2,967,750 字节；观察到 LCP 约 5.2 秒。这里的前后时间来自不同服务器，不能作为同源线上提速结论；发布后补充同一线上地址的观察。

本地发布预览显示 24 张路线卡片；已打开成都 CD-01、广州新批次、昆明新批次的地图、照片页、餐饮页和菜单弹窗，并查看窄屏截图。记录中没有页面异常或本地资源 404。属于浏览器观察，不是自动化测试套件，也不是真实手机耗时。
